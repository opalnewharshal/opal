# OPAL Governance

## Overview

OPAL (Outcome-Predictive Agent Layer) is an open-source Kubernetes project.
This document defines the governance model for the project.

## Maintainers

Maintainers are responsible for the technical direction, release management,
and overall health of the project. The current maintainer list is stored in
[MAINTAINERS.md](MAINTAINERS.md).

### Maintainer Responsibilities

- Review and merge pull requests
- Triage issues and feature requests
- Manage releases
- Represent the project at community events
- Ensure the project follows open source best practices

### Becoming a Maintainer

Contributors who have made significant and sustained contributions may be
nominated as maintainers by an existing maintainer. Nominations require
approval by a simple majority of existing maintainers.

## Contributors

Anyone who submits a pull request, files an issue, or contributes to
documentation is a contributor. Contributions of all kinds are welcome.

## Decision Making

- **Day-to-day decisions**: Made by any maintainer via pull request approval
- **Significant changes**: Require approval from at least 2 maintainers
- **Breaking changes**: Require approval from a majority of maintainers and a
  public comment period of at least 7 days
- **Governance changes**: Require approval from all maintainers

## Conflict Resolution

Disagreements between maintainers are resolved by majority vote.

## Open Source Values

OPAL is built on [kagent](https://kagent.dev), a CNCF Sandbox project.
We follow the spirit of the
[CNCF Code of Conduct](https://github.com/cncf/foundation/blob/main/code-of-conduct.md)
and are working toward CNCF Sandbox submission once we have established
community adoption.

## Meetings

Community discussions happen via
[GitHub Discussions](https://github.com/opalnewharshal/opal/discussions).

## Amendments

This governance document may be amended by a unanimous vote of all maintainers.
